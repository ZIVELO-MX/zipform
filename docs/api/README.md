# TLOZ Data API

## Objective

Version 2 introduces a shared document contract for Projects, Missions, and
Inventory. Version 1 routes remain available for one compatibility release.

The source of truth is [`openapi.yaml`](./openapi.yaml). OpenAPI defines the machine-readable HTTP contract; Swagger UI will render that contract and provide an authenticated explorer.

## Authentication

### Human users (session cookie)

Logged-in users authenticate via their NextAuth session cookie. The API resolves the user by matching the session email against the `UserProfile` table.

### Bearer authentication (personal or agent API key)

Human and agent users can authenticate API requests with a key sent as a Bearer token. The resolved user is the owner of that key:

```http
Authorization: Bearer tloz_<64-hex-chars>
```

API keys are generated by the server, hashed with scrypt (salt:hash format stored in `api_keys`), and returned only once at creation. The raw key is never persisted. Human users can create personal keys from their active browser session; Platform Owners can also manage keys for automation agents. For interactive work delegated to an agent, prefer the human owner's personal key so authorization and activity remain attributable to that user.

```http
POST /api/v1/agents
Content-Type: application/json

{ "name": "Zibot", "username": "zibot", "email": "zibot@tloz.ai", "role": "agent:operative" }
```

Response includes the agent user and the raw API key:

```json
{
  "user": { "id": "...", "name": "Zibot", "type": "agent", ... },
  "apiKey": { "key": "tloz_...", "apiKey": { ... } }
}
```

The raw API key must be stored securely (e.g., in environment variables, a secrets manager, or a `.env` file) — it cannot be retrieved later. Lost keys can be revoked and re-created:

```http
POST /api/v1/users/me/api-keys             # create personal key (browser session)
DELETE /api/v1/users/me/api-keys/{keyId}   # revoke personal key (browser session)
POST /api/v1/agents/{agentId}/api-keys     # create agent key (browser session)
DELETE /api/v1/agents/{agentId}/api-keys/{keyId}  # revoke agent key (browser session)
```

The current authorization baseline restricts `agent:reader` to sanitized TLOZ
reads. The approved target policy and its implementation status are documented in
the [TLOZ operational permission matrix](./tloz-permission-matrix.md); enforcement
of the complete matrix is tracked by TLO-0026.

## Endpoints

### Document API v2

The same endpoint supports JSON and canonical Markdown with YAML frontmatter.
Mutations require `If-Match: "<revision>"`; responses return the new revision
in `ETag`.

|--------|----------|---------|
| `GET`, `POST` | `/api/v2/documents` | Search or create documents |
| `GET`, `PATCH`, `DELETE` | `/api/v2/documents/{documentId}` | Read or mutate a document |
| `GET` | `/api/v2/document-definitions/{definitionKey}` | Read collection or child view configuration |
| `GET`, `PUT` | `/api/v2/documents/{documentId}/document` | Export or replace Markdown |

| `DELETE` | `/api/v2/documents/{documentId}/resources/{resourceId}` | Remove a resource |

## Architecture

```text
Swagger UI (/api-docs)
        │ reads
        ▼
OpenAPI document (/api/openapi)
        │ describes
        ▼
Next.js Route Handlers (/api/v1/*)
        │ authenticateRequest()
        ▼
@tloz/data repositories
        │
        ▼
PostgreSQL
```

- Implement endpoints as Next.js Route Handlers under `apps/dashboard/app/api/v1`.
- Authenticate with `authenticateRequest()` in `lib/api-auth.ts`: checks `Authorization: Bearer <key>` first, then falls back to NextAuth session cookie. This ensures an agent API key takes priority over any browser session attached to the same request.
- API keys are hashed with scrypt (`salt:hash`), stored in the `api_keys` table, and verified with `timingSafeEqual`.
- Route handlers validate inputs but delegate all business logic to `@tloz/data`.
- Return the shared `ApiError` envelope for expected failures.
- Keep Swagger UI disabled from indexing and require the same authenticated session as the API.

## Agent workflow example

1. Create a personal key from Configuración or create an agent key as Platform Owner.
2. Store the raw key securely as `TLOZ_TOKEN` in the environment that launches the agent.
3. Verify identity with `GET /api/v1/users/me`.
4. Agent queries or mutates missions with `Authorization: Bearer $TLOZ_TOKEN`; authorization follows the resolved owner.
5. Agent adds resources/dependencies as permitted by that owner.

## Security notes

- Raw API keys are returned exactly once at creation. There is no mechanism to retrieve a lost key — only revoke and re-create.
- The `.env` file at the monorepo root may hold `TLOZ_TOKEN` for local development. Production keys belong in Vercel Environment Variables or a secrets manager.
- `apps/dashboard/.env.local` is deleted; all environment variables are loaded from the root `.env` by `next.config.mjs`.

## Definition of done

- Every documented operation has authentication and automated tests.
- Swagger UI can execute a user lookup from an authenticated Preview deployment.
- Responses never include password hashes, session data, or secrets.
- Pagination has deterministic ordering and a maximum page size of 100.
- Runtime errors use a stable error code and request ID without exposing stack traces.
